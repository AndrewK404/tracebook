# Leibniz Platform — Принципы

Архитектурные решения и догматы, которые мы держим, чтобы не растечься. Извлечено из исследований `researches/007-agentic-platforms.md` и `researches/008-deep-dive-agentic-layer.md` плюс собственные продуктовые решения.

---

## 0. Главная цель

**Leibniz — это open-source general-purpose agentic layer.**

Стартуем как user-friendly **локальный дашборд для Claude Code** — это
наш якорь и первая поверхность. Дальше расширяемся **пошагово**:
другие CLI-агенты (Codex, Gemini, Aider, Goose), общая память с MCP,
workflow-оркестрация, approval inbox, observability, multi-agent sync,
и в конце — managed cloud + team mode для enterprise.

Каждый шаг — самостоятельная ценность для пользователя, а не «когда-нибудь
будет общий продукт». v0 — дашборд, который полезен сам по себе. v1 —
approval inbox, полезный сам по себе. И так далее.

Никакого «Большого Перепрыгивания» в universal agent platform одним релизом.

## 1. Терминал — это субстрат, мы строим UI поверх него

**Принцип:** реальная работа агентов остаётся в терминале пользователя. Пользователь продолжает использовать `claude`, `codex`, `gemini`, `aider`, `goose` — со своей собственной подпиской, через официальные CLI. Мы **не** заменяем эти инструменты, **не** проксируем их инференс, **не** трогаем их OAuth-токены.

Поверх терминала мы строим **UI-слой**: дашборды, workflow-оркестрация, память, наблюдаемость, мульти-агентная синхронизация.

**Почему это правильно:**

- Обходим ToS-мину Anthropic (третья сторона не имеет права использовать Claude OAuth-токены вне Claude Code) — потому что мы вообще их не трогаем. Подпиской пользуется официальный `claude`, мы его только наблюдаем и оркестрируем.
- BYOK по определению: пользователь платит Anthropic/OpenAI напрямую, мы не берём наценку на токены.
- Никакой провайдерской привязки: любой CLI, который умеет в stdio + JSONL, нам подходит.
- Нулевой риск бана аккаунта — потому что наш код вообще не делает API-вызовов к моделям.
- Совместимость с экосистемой Claude Code «бесплатно»: skills, hooks, slash-команды, MCP-серверы пользователя продолжают работать.

**Что это значит технически:**

- Мы работаем через **stdio / pty / JSONL-сессии** официальных CLI. Спавним `claude --print --output-format stream-json` (или эквивалент Codex), читаем его поток событий, отрисовываем в нашем UI.
- Hooks (`PreToolUse`, `PostToolUse`, `Stop`, и т.д.) — наш главный канал телеметрии. Регистрируем хуки у официальных CLI, получаем события в наш демон.
- JSONL-транскрипты в `~/.claude/projects/...` — источник истины для истории. Мы их парсим, индексируем, строим над ними память.
- MCP-серверы пользователя — тоже наши: подключаемся к тем же серверам, что и Claude Code, через стандартный протокол.

**Чего мы НЕ делаем:**

- Не пишем свой агент-рантайм-обёртку, которая делает вид, что она Claude Code (это и юридически серая зона, и технически — `anthropic-beta: claude-code-20250219` гейт всё равно сломает).
- Не проксируем `api.anthropic.com` через свой сервер.
- Не предлагаем «логин через Claude» в нашем UI.

## 2. UI поверх терминала, не вместо терминала

Терминал — это **рабочий орган**, наш UI — **диспетчерская**.

В UI:
- **Dashboards** — текущие сессии, токены за день/неделю, какие агенты работают, какие тулы вызывались, какие файлы трогали.
- **Workflows** — визуальная композиция: «когда `claude` доделал X, запусти `codex` на Y, прокинь артефакт Z». DAG над несколькими CLI-сессиями.
- **Memory** — общая база знаний (транскрипты, коммиты, скриншоты, заметки) с провенансом, к которой агенты обращаются как к MCP-серверу.
- **Observability** — таймлайн всех tool-вызовов, права/approvals, диффы, артефакты.
- **Multi-agent sync** — несколько параллельных агентов с file-mailbox IPC (паттерн Claude Code), но видимым в UI.

Терминал остаётся доступен в любой момент — ни одна функция UI не блокирует прямую работу через CLI.

## 3. OSS-core, BYOK навсегда, monetize выше слоя инференса

- **Apache 2.0** на ядро + trademark policy + CLA с первого дня (опция уйти в FSL, если гиперскейлер начнёт встраивать).
- **Никогда** не берём наценку на токены. Инференс идёт через подписку пользователя, мы только за ценность сверху (UI, память, оркестрация, governance, hosting).
- Цена: $0 для индивидуального использования, $25–40/seat/мес за Cloud Team, $75–125 за Cloud Business, $25–150к/год за Enterprise self-host.
- Что закрыто: managed hosting, мульти-юзерная память, SSO/SCIM enforcement, audit logs, RBAC, compliance-сертификации, governance UI.
- Что открыто навсегда: ядро, single-user CLI, локальная SQLite-память, все адаптеры, плагин/skill SDK.

## 4. Минимальное защитимое ядро

Десять примитивов, всё остальное — фичи поверх:

1. `Session` — типизированная сессия (thread_id, messages, state, metadata).
2. `Message` — discriminated union (User/Assistant/ToolUse/ToolResult/System), модель блоков Anthropic.
3. `Tool` — `(name, description, input_schema, handler)`, JSON Schema из Pydantic.
4. `AgentLoop` — канонический цикл с stop-conditions (но мы его в основном не сами крутим — за нас крутит официальный CLI; наш `AgentLoop` нужен для оркестрации поверх).
5. `Hooks` — `PreToolUse / PostToolUse / OnMessage / OnError / OnStreamEvent / OnInterrupt`.
6. `Checkpointer` — `save / load / list`, дефолт SQLite.
7. `Interrupt / Command(resume=...)` — паттерн LangGraph для HITL.
8. `StreamEvent` — discriminated events, единый поток для UI.
9. `ProviderAdapter` — адаптер не к API провайдера, а к **CLI** провайдера: `ClaudeCodeAdapter`, `CodexAdapter`, `GeminiCLIAdapter`, `AiderAdapter`. Спавнит подпроцесс, парсит JSONL, эмитит наши `StreamEvent`.
10. `MemoryStore` — Letta-подобные блоки `core / recall / archival`.

## 5. Стек

- **Язык клиента (TUI):** TypeScript на Bun + Ink. Совпадает с экосистемой Claude Code / Codex / Copilot CLI.
- **Язык демона:** Python + FastAPI. Экосистема memory/RAG/MCP-Python — слишком ценная, чтобы перепиывать обёртки на Go/Rust ради бинарного размера.
- **Транспорт CLI ↔ демон:** Unix domain socket с newline-delimited JSON-RPC 2.0 по умолчанию; опционально `localhost:port` HTTP+SSE для удалённого доступа. Файл-мейлбокс для inter-agent IPC.
- **Хранилище:** SQLite + sqlite-vec embedded в v1; путь миграции на Postgres + pgvector в v2 team mode (через repository-абстракцию).
- **Память:** Graphiti (bi-temporal KG, Apache 2.0) поверх Kuzu (embedded) для OSS, Neo4j для enterprise. Отдельная Postgres governance plane с RLS, ACL, OpenLineage-эвентами — это наш клин.
- **Протоколы:** MCP (stdio + Streamable HTTP) и A2A (JSON-RPC + REST) — first-class. ANP и gRPC — пропускаем v1.
- **Sandboxing:** маленький Rust-helper для OS-level (Landlock+seccomp / Seatbelt / AppContainer) — единственное место, где отступаем от «TS+Python везде».
- **Packaging:** `uv tool install leibniz` основной путь; PyInstaller-бинари как опциональная альтернатива; Tauri 2 desktop shell позже.

## 6. Что мы строим, в одной фразе

**Leibniz** — это диспетчерская для агентских CLI. Терминал делает работу, мы даём дашборды, оркестрацию workflow и общую память поверх него — со своей подпиской, со своими CLI, без OAuth-минного поля и без наценки на токены.

---

## 7. Что мы НЕ делаем

- Не клонируем Claude Code / Codex / Aider. Они уже хороши.
- Не строим горизонтальный «Copilot для всего» — это проигрышный бой против Microsoft.
- Не делаем yet-another-agent-framework — LangGraph / OpenAI SDK / Claude Agent SDK уже покрывают пространство.
- Не продаём токены и не маркапим инференс.
- Не трогаем подписочные OAuth-токены пользователя третьим способом.
- Не делаем web-only продукт. Терминал — субстрат, и точка.

---

## 8. Якоря и компасы

- **Каждый раз, когда возникает соблазн «давайте сами вызовем модель»** — стоп. Это делает CLI пользователя.
- **Каждый раз, когда возникает соблазн «давайте проксируем токены»** — стоп. Не делаем.
- **Каждый раз, когда возникает соблазн заменить терминал нашим UI** — стоп. UI поверх, не вместо.
- **Каждый раз, когда возникает соблазн закрыть OSS-ядро** — стоп. Закрываем enterprise plane (cloud, governance, audit), не ядро.
- **Решение, которое нельзя откатить за неделю, проходит через явный документ.** Принципы — не догма, но изменение этого файла = осознанная сделка.
